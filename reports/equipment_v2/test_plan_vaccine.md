# 예방접종 모델·기준 모델 test 평가 사전 계획 (6개, 원본 성능 + 장치 설정 필터 시험)

작성: 2026-10-22 오후 4시경, **예방접종·기준 모델의 test 점수를 보기 전**. 이 문서와 코드·모델의 해시를 `test_plan_vaccine.sha256`에 고정한 뒤 test를 모델마다 한 번씩만 연다. `reports/test_eval/evaluation_plan.md`와 `test_plan_B512.md`는 수정하지 않는다. 학습 계획은 `vaccine_plan.md`(결과 전 고정)다.

## 1. 알려 둘 것 (사후 결정과 test 접촉 내역)

- test 624장은 이미 10/19에 224 모델 8개로, 10/22에 B512로 평가했다. **이번 평가는 "이미 열린 test에서의 사전 지정 추가 분석"이다.** 가이드가 추가 사용을 허용하는지는 강사 확인을 권한다.
- **예방접종 모델의 설계(증강 종류·세기·확률)를 정할 때 B512의 test 결과는 이미 알려져 있었다.** 다만 설계 근거는 장비 물리 사전지식과 val 필터 시험 결과뿐이라고 `vaccine_plan.md`에 적었고, test에서 얻은 가설(경계 강조가 정상 recall을 올림 등)은 쓰지 않았다. 그러나 test 결과를 알고 있었던 사람의 판단이 완전히 독립이었다는 것은 증명할 수 없다.
- 학습 환경은 SageMaker JupyterLab(ml.g4dn.xlarge, torch 2.8)이다. AWS 학습 작업(torch 2.2)의 B512(seed 42)와 환경이 다르다.
- 에폭 선택은 6개 모두 학습 계획의 규칙(원본 val Macro-F1 최고 에폭)이다. 결과를 보고 바꾸지 않았다. (b-s43은 에폭 1이 선택됐다. 에폭 20과 val F1이 0.0001 차이였다. 규칙대로 그대로 쓴다.)
- val 평가(학습 계획 3장)는 모두 끝난 뒤 판정하지만, 이 test 계획은 6개의 val 결과 전체를 보기 전에 고정한다. 계획이 val 결과에 따라 달라지지 않도록, 아래 내용은 val 결과와 무관하게 정했다.
- 가로세로 비율·해상도 손실 진단은 val만 썼고 설계 변경에 쓰지 않았다.

## 2. 평가 대상

- 모델 **6개 전부**: v-s42, v-s43, v-s44 (예방접종), b-s42, b-s43, b-s44 (기준). seed 42·43·44. 어떤 모델도 val·test 점수를 보고 빼거나 고르지 않는다.
- 6개가 한꺼번에 끝나지 않았으므로 끝난 것부터 평가하고(지금 4개: v-s42, b-s42, v-s43, b-s43), 나머지 2개(v-s44, b-s44)는 끝나는 대로 **같은 계획**으로 평가한다. 먼저 평가한 4개의 test 결과를 보고 나머지 2개의 평가 방법이나 해석 규칙을 바꾸지 않는다. 나머지 2개의 모델 파일 해시는 평가 직전에 `test_plan_vaccine.sha256`에 덧붙인다(모델이 아직 없어서 지금 고정할 수 없다).
- 참고로 AWS B512(seed 42)의 test 결과는 이미 있다(`test_B512`). 환경 차이 확인용으로만 비교한다.
- 데이터: test 624장 중 같은 사진(sha256) 6쌍의 사본을 뺀 **618장** (정상 231 / 세균성 240 / 바이러스성 147, 환자 묶음 426). 규칙은 B512 평가와 같다.

## 3. 평가 내용 (모델마다 `src/equipment_eval_direct.py --split test`)

1. **원본 성능:** Macro-F1과 95% 구간(환자 묶음 단위 bootstrap 1,000번), Macro-AUROC, 클래스별 recall, 혼동행렬.
2. **필터 시험:** `strength_fixed_512.md`와 같은 33조건(같은 강도, 노이즈 seed = 42 + 사진 번호)을 걸어 원본 test 대비 Macro-F1 변화와 95% 구간을 잰다. **33조건 전부 실행하고 전부 보고한다.**
3. **요약(6개가 다 있을 때):** 모델 묶음별로 (a) 원본 test Macro-F1, (b) 학습에 쓴 5종(선량·조사시간·산란·kVp·센서, 15조건)의 평균 Macro-F1, (c) 학습에 쓰지 않은 3종(경계 강조·대비 보정·JPEG, 9조건)의 평균 Macro-F1, (d) 부록 3종(흐림·밝게·어둡게, 9조건)의 평균을 구한다. 각 값은 seed 3개의 평균 ± 표준편차, 예방접종 − 기준의 차이도 적는다.
4. **판정 규칙:** `vaccine_plan.md`와 같다. 예방접종 − 기준의 평균 차이가 **기준 모델 3개의 seed 표준편차(같은 지표)의 2배 이상**일 때만 "차이가 있다"고 쓰고, 아니면 "차이를 말할 수 없다". 학습에 쓴 5종은 배운 유형이라 방어력의 증거로 쓰지 않고, 쓰지 않은 3종이 방어력을 보는 부분이다. 원본 test F1이 기준보다 표준편차 이상 떨어지면 원본 성능 손실로 함께 보고한다.
5. 모델이 6개가 못 되면(끝나지 않거나 실패) 있는 것만 보고하고, 어느 쪽이든 seed가 3개 미만이면 판정 규칙을 쓰지 않고 "참고 수준"으로만 적는다.
6. val 점수와 test 점수는 같은 표로 나란히 적는다(val과 test의 순위가 달랐는지 포함).

## 4. 규칙

- 모델마다 해시를 고정한 뒤 한 번만 실행한다. 결과가 어떻든 모델·필터·강도·방법·판정 규칙을 바꾸지 않는다. 결과 파일이 만들어지지 않은 코드 오류가 났을 때만 재실행하고 이유를 기록한다.
- test 점수를 보고 모델·설정·seed를 고르지 않는다.
- 계산 장치는 노트북 GPU(mps)다. val에서 AWS GPU와 같은 결과를 확인했다.
- 스크립트는 이 문서의 sha256을 받아야만 test를 연다 (`--plan-file`, `--plan-sha256`).

## 5. 해석할 때 미리 적어 두는 한계

- test 정상 사진은 저장 화질(약 75 vs 96)과 가로세로 비율이 train·val과 달라서, 지금까지 모든 모델에서 val보다 test 점수가 낮았다. 절대 점수보다 **원본 test 대비 변화**와 예방접종 − 기준 차이를 중심으로 해석한다.
- seed 3개라 작은 차이는 구분하지 못하고, 표준편차 추정도 거칠다. 에폭 선택 규칙 때문에 기준 모델의 seed 편차가 커질 수 있다(b-s43처럼).
- 필터는 실제 장비가 아닌 흉내이고, 필터끼리 강도가 보정되지 않았다. 학습 세기의 상한이 '강'이라 그보다 센 조건은 보지 않았다.
- 학습에 쓰지 않은 유형이 완전히 낯선 것은 아니다(경계 강조·대비 보정은 산란·kVp와 효과 계열이 겹칠 수 있고, 제조사 후처리는 대표 기법일 뿐이다).
- val에서 낫다는 것이 test에서도 낫다는 보장이 없다(지금까지 val과 test의 모델 순위는 일치하지 않았다).
- test 세균성 환자 77명뿐, 한 병원 데이터, 환경이 다른 AWS B512와의 비교는 환경 차이가 섞인다.
